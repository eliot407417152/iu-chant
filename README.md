# IU 應援歌單

以專輯與單曲分類、依發行日期排列的 IU 應援網站。歌曲清單來自 `backend/src/main/resources/seed/catalog.json`（共 37 張專輯／單曲、150 首歌，不含純音樂版），歌詞與應援法之後再逐首補上。

```
iu-chant/
├── backend/            Spring Boot 3 + JPA（Java 17+）
│   ├── pom.xml
│   ├── http/api.http   IntelliJ HTTP Client 測試檔
│   └── src/main/
│       ├── java/com/example/iuchant/
│       │   ├── album/      專輯：Album、AlbumController（GET /api/albums）
│       │   ├── song/       歌曲：Song、LyricLine、歌詞與應援法 API
│       │   ├── catalog/    清單匯入：啟動時匯入 catalog.json，也可用 API 匯入
│       │   ├── backup/     備份：匯出／匯入所有影片、應援歌單順序與歌詞
│       │   └── config/     CORS、管理金鑰
│       └── resources/seed/catalog.json   專輯與歌曲清單
├── frontend/           Next.js 15 + TypeScript
│   ├── app/            首頁（專輯列表）、歌曲頁
│   ├── components/     AlbumBrowser、LyricsPlayer、Editor、TimeInput、AdminHome、BackupPanel、AdminProvider、TopBar、ThemeToggle
│   ├── hooks/          useYouTubePlayer
│   └── lib/            型別、API 呼叫、播放佇列 queue、歌詞解析 parseLyrics
├── tools/parse_catalog.py   把 iu專輯以及單曲.md 轉成 catalog.json
└── docker-compose.yml  選用：PostgreSQL
```

## 需要的環境

- JDK 17 以上
- Node.js 20 以上
- IntelliJ IDEA（Community 或 Ultimate 都可以）

## 用 IntelliJ 開始

1. **File → Open**，選整個 `iu-chant` 資料夾。
2. 在 `backend/pom.xml` 上按右鍵 → **Add as Maven Project**，等 Maven 下載完成。
3. 確認 Project SDK 是 JDK 17 以上。
4. 打開 `IuChantApplication.java`，按 `main` 旁的綠色三角形執行。看到 `已匯入 37 張專輯／單曲、150 首歌` 就成功了。
5. 開 `backend/http/api.http`，執行第一個請求，確認有專輯資料。
6. 在 IntelliJ 的 Terminal 執行：

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

7. 瀏覽器打開 http://localhost:3000 。

> **從舊版升級：** 這次新增的欄位（演唱會影片、歌詞所屬版本）設計成可以直接加在舊資料庫上，**不用刪資料**。舊的歌詞會自動歸在「應援版本」。升級前仍建議先複製一份 `backend/data/` 當保險。

預設用 H2 檔案資料庫（`backend/data/`），不用安裝資料庫。改用 PostgreSQL：`docker compose up -d`，並把 Active profiles 設成 `postgres`。

## 首頁功能

- 預設由新到舊（最新的 2026 在最上面），可切換為由舊到新
- 分類：全部、**應援歌單**、正規專輯（含改版）、迷你專輯、單曲、**翻唱專輯**（花書籤 1～3）、**OST**（電視劇 OST 曲目）
- 「跳到專輯」下拉選單與「排序」按鈕固定放在分類列右邊（畫面較窄時固定換成下一列），切換分類時位置不會亂跑
- 每首歌顯示曲序、主打、Feat.、備註、時長；已整理應援法的會出現「應援法」標籤
- 「全部」頂端有應援歌單卡片，按「播放全部」就從第一首開始連播

專輯封面沒有上傳時，會顯示依專輯產生的色塊。封面請在管理員模式上傳（見下方「專輯封面」）。

## 應援歌單與連續播放

應援歌單共 17 首，順序寫在 `tools/parse_catalog.py` 的 `CHANT_ORDER`，由新到舊。要增減或調整順序，可以在管理員模式裡改每首歌的「應援歌單順序」。

- **從應援歌單進入**（`?list=chant`）：播完自動播下一首，最後一首播完會回到第一首循環。沒有影片的歌會自動跳過。
- **從專輯進入**（預設）：播完自動播同一張專輯的下一首，最後一首播完就停止。
- 歌曲頁下方有「單曲循環」和「播完自動播下一首」開關，會記在瀏覽器裡。
- 自動連播靠的是瀏覽器的自動播放：第一次要自己按一下播放（或按「播放全部」），之後切換歌曲才不會被瀏覽器擋住。

## 外觀

- **深色模式：紫色**；**淺色模式：白色**（強調色仍是紫色）。淺色模式的文字對比都在 6:1 以上，還沒唱到的歌詞也不會變淡。
- 右上角的「外觀」是三選一的選項（跟隨系統／淺色／深色），直接點想要的就好，選擇會記在瀏覽器裡。

## 應援的顯示方式

不再用括號，而是用不同顏色的字：

| 類型 | JSON 值 | 說明 |
|---|---|---|
| 跟唱 | `sing` | 大家一起唱這句歌詞，空耳（`roman`）會顯示在上方 |
| 喊口號 | `call` | 歌詞之外要喊的詞 |
| 歡呼 | `cheer` | 歡呼 |
| 拍手／安靜／全體 | `clap` / `quiet` / `all` | 備用 |

每一行的資料：`startSec`（秒）、`text`（歌詞或要喊的詞）、`roman`（空耳）、`sub`（翻譯）、`chant`（類型，不是應援就省略）。歌曲頁會在歌詞上方顯示顏色說明，播放器下方會提示「接下來」的應援。

## API

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/api/albums` | 所有專輯與單曲，含歌曲摘要，依發行日期由舊到新 |
| GET | `/api/albums/{slug}/cover` | 管理員上傳的專輯封面圖 |
| PUT / DELETE | `/api/admin/albums/{slug}/cover` | 上傳（請求內容是圖片，Content-Type 為 image/jpeg、png 或 webp）／移除封面，需要 `X-Admin-Key` |
| GET | `/api/songs/{slug}` | 單首歌，含四種影片、各版本歌詞與應援法 |
| GET | `/api/admin/backup` | 匯出備份（JSON），需要 `X-Admin-Key` |
| POST | `/api/admin/backup/restore` | 匯入備份，需要 `X-Admin-Key` |
| GET | `/api/admin/ping` | 驗證管理金鑰（管理員登入用），需要 `X-Admin-Key` |
| PUT | `/api/admin/songs/{slug}/content` | 更新一首歌的影片、應援歌單順序與各版本歌詞，需要 `X-Admin-Key` |
| POST | `/api/admin/catalog/import` | 新增新發行的專輯或單曲，需要 `X-Admin-Key` |

管理金鑰在 `application.yml` 的 `app.admin-key`，預設 `change-me`，上線前一定要改。

## 管理員模式

公開頁面上**不會有任何管理員入口**，一般訪客看不到。要進入管理員模式，直接在網址列輸入 `/admin`（例如 http://localhost:3000/admin）：

1. 輸入管理金鑰（預設 `change-me`）登入。登入狀態會記在這台裝置的瀏覽器，登入後右上角才會出現「管理員模式」與「登出」。
2. 管理頁會列出所有專輯與歌曲，並標示哪些已有影片、應援法、是否在應援歌單。點任何一首進入編輯。
3. 登入後，每個歌曲頁右上角也會出現「編輯這首歌」。

### 專輯封面

管理員頁面裡，每張專輯標題下面都有封面縮圖與「上傳封面／更換封面／移除封面」。選一張圖片就會自動縮成長邊 800 像素以內的 JPEG 再上傳，不用自己先處理大小。

- 上傳後管理員頁面立刻看得到；公開頁面在正式環境（`npm run build` 後）最多幾分鐘內更新，開發模式（`npm run dev`）則是重新整理就更新。
- 封面存在資料庫裡，也會一起包進備份檔。

### 備份與還原

管理員頁面上方有「備份與還原」：

- **匯出備份**：下載一個 JSON 檔，內容是所有專輯（含上傳的封面）、歌曲、四種影片、應援歌單順序與每個版本的歌詞。
- **匯入備份**：選擇之前匯出的 JSON。會依歌曲代稱（slug）覆蓋該歌曲的影片、順序與歌詞，沒有的專輯或歌曲會新增；**備份檔裡沒有的歌曲不會被刪除**。匯入前會先跟你確認，建議先匯出一份目前的資料。
- 換電腦、重建資料庫、或改歌詞前想留個保險，都可以用這個。

### 編輯一首歌

- **四種影片**：應援版本、MV、純音樂、**LIVE版**，各貼 YouTube 網址（或 11 碼影片 ID），沒有的留空。歌曲頁會依有哪幾種顯示切換按鈕，預設先顯示應援版本。
- **每個版本各自的歌詞**：左邊選到哪個版本，播放器就顯示那支影片，下面的歌詞與打點也是在編輯那個版本，彼此獨立。每個版本旁會顯示目前有幾行歌詞。
  - 某個版本的歌詞文字跟另一個版本一樣、只有時間不同時，用「從其他版本帶入歌詞…」把文字帶過來（時間會清空），再重新打點。
  - 某個版本還沒有自己的歌詞時，歌曲頁會暫時借用其他版本的歌詞，並提示時間可能對不上。
- **歌詞偏移（秒）**：歌詞時間 = 播放時間 + 偏移。每個版本既然有自己的歌詞，通常填 `0` 就好；舊資料或借用其他版本歌詞時才用得到。
- **應援歌單順序**：填數字就會加入應援歌單，留空就移出。
- **歌詞與打點**：貼上歌詞按「解析」，播放影片，在每一行開始唱的瞬間按空白鍵打點（已自動提早 0.3 秒）。上下方向鍵移動目前行。每一行的時間用「分」和「秒」兩格輸入（例如 1 分 23.4 秒），「播放」可以確認位置。
- 只想設定影片的話，不用貼歌詞，直接按「儲存」。

歌詞文字的格式：

- 一行歌詞後面緊接一行翻譯。
- 用 `(( ))` 包起來的是應援。緊接在歌詞前面的一行是那句的空耳，整句會標為「跟唱」。
- 其他連續的 `(( ))` 行是一組喊口號：3 行依序是空耳、要喊的詞、意思；2 行時，含韓文的是要喊的詞；1 行是要喊的詞（含「歡呼」則標為歡呼）。
- 空白行分隔段落，以 `*` 開頭的行是備註，會被略過。

管理員頁面沒有從公開頁面連過去，真正的保護是管理金鑰，上線前務必修改 `app.admin-key`。曲名、專輯等基本資料來自 `catalog.json`，管理員模式不修改它們（備份還原會一併還原這些基本資料）。

## 新增新發行的專輯

1. 在 `tools/iu專輯以及單曲.md` 加上新的段落（格式照其他專輯；翻唱專輯的標題要含「翻唱」兩個字）。
2. 在專案根目錄執行 `python tools/parse_catalog.py "tools/iu專輯以及單曲.md" backend/src/main/resources/seed/catalog.json`。
3. 重新啟動後端。啟動時如果發現 `catalog.json` 裡有資料庫還沒有的專輯，會**自動補上**；已存在的專輯完全不動，所以不會蓋掉你改過的影片與歌詞。（也可以用 `POST /api/admin/catalog/import` 手動送出，格式見 `api.http`。）

## 清單轉換規則

- 「熱門 OST 曲目」每首 OST 是一個單曲項目，類別寫「OST」；曲名後面的 *(…)* 備註（例如「演唱會安安可點歌常客」）會顯示在曲目下方。沒有時長的未發行音源（德魯納酒店片尾曲）時長記為 0，列表不顯示時間。

- 純音樂版（Inst.）不收錄，共排除 9 首。
- 主打歌（md 裡用粗體標示）會顯示「主打」。
- `(Feat. …)`、`(With …)`、`(Prod. & Feat. …)` 會拆成 Feat. 欄位。
- 《Modern Times – Epilogue》只收錄新增的 2 首，備註其餘曲目同原專輯。
- 同一首歌收錄在不同專輯時會各自列出（例如《Lost and Found》與《Growing Up》都有〈미아〉），網址代稱會自動加上專輯名稱區分。

## 常見問題

- **前端顯示「無法取得專輯列表」**：後端沒啟動，或 `API_URL` 不對（預設 `http://localhost:8080`）。
- **啟動時出現資料表欄位錯誤**：刪除 `backend/data/` 後重啟。
- **Maven 下載失敗**：檢查網路，或在 Maven 面板按重新載入。
